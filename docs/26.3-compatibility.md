# Fabric 26.3 port

Use Java 25, Minecraft **26.3**, Fabric Loader **0.19.5 or newer**, and Fabric API **0.163.0+26.3**. The jar intentionally rejects other Minecraft versions because its mixins target 26.3 signatures.

## Rendering

First-person items and maps are extracted before rendering. Arms, items, maps, chest/shulker poses, and breaking overlays are submitted through Minecraft's render collectors and render types. Locomotion does not call OpenGL or Vulkan directly, install shaders, or force a graphics backend. Minecraft owns GPU buffers, pipelines, and render passes.

Model transforms are copied before converting pixel translations to block units. Deferred block-entity rendering carries a sampled pose, rather than querying a live animation container during GPU submission. Resource reloads apply on the supplied game executor and reset cached animation data. Disconnects also reset caches. When first-person assets/poses are unavailable, vanilla hand rendering remains available.

## Reproduce verification

Set `JAVA_HOME` to JDK 25. The tests create disposable worlds under `build/run/clientGameTest`; they do not use launcher worlds or the launcher's mods directory.

```powershell
.\gradlew.bat build compileGametestJava
.\scripts\Test-Compatibility.ps1
```

The script checks the minimal mod set and the rendering profile (Sodium, 3D Skin Layers, Mod Menu, YACL) on both backends, plus the full profile including Iris on OpenGL. It explicitly skips Iris + Vulkan as an unsupported upstream combination, not as a passing test. Logs and screenshots go under `build/compatibility`. Tests assert the actual selected GPU backend; silent fallback to OpenGL fails a Vulkan test. The game window requires a working desktop and graphics driver.

Individual runs work on other operating systems with `./gradlew`:

```text
./gradlew runClientGameTest -PgraphicsBackend=opengl
./gradlew runClientGameTest -PgraphicsBackend=vulkan
./gradlew runClientGameTest -PgraphicsBackend=opengl -PconfigUi=true -PcompatMods=iris,skinlayers
./gradlew runClientGameTest -PgraphicsBackend=vulkan -PconfigUi=true -PcompatMods=sodium,skinlayers
```

The full profile includes these pinned versions:

| Mod | Version |
| --- | --- |
| Sodium | 0.9.2 for 26.3, Fabric |
| Iris | 1.11.7 for 26.3, Fabric |
| Mod Menu | 21.0.0 |
| YACL | 3.9.7+26.3-fabric |
| 3D Skin Layers | 1.11.3 for 26.3, Fabric |

`-PcompatMods=sodium` is also available for testing Sodium separately. These dependencies are only added to the development runtime; none are bundled into the mod jar. YACL and Mod Menu remain optional.

The client test checks resource loading, repeated model transforms, configuration screen rendering, first-person frame availability, swapping and using 11 item types, left/offhand rendering, chest/shulker opening and breaking overlays, third-person rendering, toggling the renderer, resource reload, and disconnect/rejoin.

Recorded local runs used Windows, OpenGL on AMD Radeon(TM) Graphics (driver string `3.3.0 Core Profile Context 26.5.2.260413`), and Vulkan on NVIDIA GeForce RTX 3050 Laptop GPU (`1.4.351 NVIDIA 616.64`). Minimal Fabric passed on both backends. Sodium + 3D Skin Layers + Mod Menu/YACL passed on both backends. The complete group including Iris passed on OpenGL; Iris + Vulkan aborted as described below. Runtime testing was stopped at the user's request; subsequent verification was compilation and jar inspection only. These results do not certify other hardware or shader packs.

## Limits

**Iris 1.11.7 + native Vulkan is incompatible.** The attempted full-profile Vulkan run aborted in `Iris.duringRenderSystemInit -> IrisRenderSystem -> SamplerLimits -> GL11C.glGetInteger` because no OpenGL context exists. This reproduces [Iris issue #3357](https://github.com/IrisShaders/Iris/issues/3357). Use OpenGL when Iris is installed, or remove Iris to use native Vulkan. Locomotion does not silently force a different backend or patch Iris's shader engine.

These are integration smoke tests, not a guarantee for every mod, shader pack, driver, resource pack, or visual interaction. Iris tests use its default configuration with no external shader pack enabled. 3D Skin Layers co-loading is tested; a custom skin's layer appearance is not covered by pixel comparisons. Multiplayer against a remote server and macOS/Linux GPU execution require separate verification. CI compiles the mod and client tests on Windows and Linux; it does not claim GPU test coverage.

The upstream project's incomplete animations and third-person placeholders remain. Forge/NeoForge and older Minecraft builds are outside this port's build.
